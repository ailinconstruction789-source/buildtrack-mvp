# Customer Voices — การตรวจผ่านเบราว์เซอร์ในเครื่อง

วันที่ 24 กันยายน 2569 ต่อจาก `sales-v2-customer-voices.md`

## ขอบเขตที่ปลอดภัย

รอบนี้เพิ่มชุดทดสอบ ไม่ได้เปิดฟีเจอร์ เปลี่ยนข้อมูลลูกค้า รัน SQL บน Supabase หรือ Deploy ไม่มีการใช้บัญชีหรือฐานข้อมูลจริง

- ใช้หน้า Next.js, ส่วนรับคำขอ และ Supabase SDK จริง แต่ปลายทางเป็น HTTP fixture ที่จำลองข้อมูลในหน่วยความจำ ฟังเฉพาะ `127.0.0.1`
- คัดลอกเฉพาะ 4 routes ของ Customer Voices, layout และ dependency closure รวม 27 ไฟล์ ไม่คัดลอกทั้งแอป ไม่คัดลอก `.env*` และไม่รับค่า credential/proxy/NODE_OPTIONS จากสภาพแวดล้อมเดิม ใช้ค่า Supabase สมมติและเปิด flags เฉพาะ process ทดสอบ
- เบราว์เซอร์ปฏิเสธการเรียก URL นอกสองปลายทางในเครื่อง ไม่มี service worker; ไม่เก็บ trace/video ใช้เฉพาะภาพและรายงานของข้อมูลสมมติ
- แยกคำสั่งทดสอบจากชุด E2E dashboard เดิมซึ่งไม่ได้ออกแบบให้แยกข้อมูลจริง และแยกออกจาก Vitest
- รันทีละ worker ไม่มีการใช้ session ของเบราว์เซอร์ส่วนตัว บัญชี Sales/Owner ที่ทดสอบเป็นบัญชีสมมติ
- ฟอนต์ใช้คำตอบจำลองแบบออฟไลน์ ภาพหน้าจอจึงไม่รับรองฟอนต์จริงบน Vercel
- ใช้ `next build` ของ snapshot ให้เสร็จและปิด compiler ก่อน `next start`/Chromium ลดช่วงใช้ RAM พร้อมกัน: heap ของ compiler 512 MiB, server 256 MiB, หนึ่ง worker, ปิด webpack cache เฉพาะ config สำเนา แต่คงการตรวจ TypeScript และ headers จาก config จริง ไม่ได้แก้ Next config ของแอป

## กรณีในชุดทดสอบ

1. Sales ออก QR พร้อมเหตุผล ภาพ QR เป็น PNG จริงและตรงกับลิงก์ที่คัดลอก อายุที่แสดง 24 ชั่วโมง การออก QR ยังไม่ทำให้ Visit สำเร็จ
2. ลูกค้าเปิดจากลิงก์ใน browser context แยก ไม่เห็นชื่อลูกค้าเดิม คะแนนทั้ง 8 ข้อว่าง รายได้ว่าง ส่งไม่ครบไม่ได้ และไม่เติมคำตอบส่วนที่ไม่ตอบ
3. เมื่อส่งสำเร็จ หน้า Sales โหลดผลแล้วแสดง Visit สำเร็จ ไม่แสดง QR เดิม การส่งหนึ่งครั้งสร้างคำตอบเดียวใน fixture
4. ลิงก์ใหม่ทำให้ลิงก์เก่าเปิดไม่ได้ และลิงก์หมดอายุไม่เปิดแบบฟอร์ม
5. จำลองบันทึกสำเร็จแต่คำตอบจากเซิร์ฟเวอร์สูญหาย: ล็อกคำตอบไว้ ไม่ส่งซ้ำเอง การตรวจผลซ้ำใช้ request ID และเนื้อหาเดิม ไม่เพิ่มจำนวนคำตอบ
6. Owner เห็นหน้าจออ่านอย่างเดียว; คำขออ่านแบบไม่มีบัญชีถูกปฏิเสธ
7. ลิงก์ผิด, token ใน query, body เกิน 16 KB, content type ผิด และ method ไม่รองรับถูกปฏิเสธ
8. เปลี่ยน QR ในหน้าเดิมแล้วซ่อนคำตอบเก่า ไม่ส่งคำตอบข้าม Visit
9. ตรวจ referrer/frame/index headers, ไม่มี token ใน network URL, public API ไม่ส่ง cookie/JWT/referrer และไม่เก็บคำตอบ/token ใน localStorage/sessionStorage
10. ขนาดหน้าจอ desktop และ Chromium จำลองมือถือ ไม่เกิดการเลื่อนแนวนอน

## วิธีรันซ้ำ

```text
node --max-old-space-size=256 --max-semi-space-size=1 node_modules/@playwright/test/cli.js test --config=playwright.voices.config.ts
```

ใช้เฉพาะคำสั่งนี้สำหรับชุดแยกข้อมูลสมมติ ไม่ต้องตั้ง `.env` หรือเปิด flags จริง ต้องมี Chromium ของ Playwright ติดตั้งอยู่แล้ว และพอร์ต 3146/3147 ว่าง สคริปต์ไม่ยึดใช้เซิร์ฟเวอร์ที่เปิดค้างไว้ โปรไฟล์ใหม่เตรียมแล้วค่อยทดสอบ ตรวจ RAM ว่างอย่างน้อย 512 MiB และ workspace disk อย่างน้อย 1 GiB ก่อนเริ่ม (เกณฑ์ขั้นต่ำ ไม่รับประกันว่าจะพอตลอดการรัน) ไม่ใช่เพียงลดเกณฑ์ของ dev-server แบบเดิมที่เปิด compiler 1536 MiB ค้างพร้อม browser

บน Windows ต้องมีสิทธิ์ปิด process tree ที่ Playwright สร้าง มิฉะนั้น `taskkill /T` อาจได้ `Access denied` แล้วตัวทดสอบรอ cleanup ไม่จบ ใน Codex รอบนี้ขออนุญาตยกระดับเฉพาะคำสั่งทดสอบ localhost ที่ระบุ ไม่ปิด Chrome/ChatGPT ของผู้ใช้ ไม่ลดการป้องกันของ Windows และไม่เปลี่ยน pagefile

เมื่อรันจบ รายงานจะอยู่ที่ `node_modules/.cache/buildtrack-voices-browser/report.json` และภาพที่ `results/` ใต้โฟลเดอร์เดียวกัน ทั้งหมดถูกละเว้นจาก Git รายงานรอบสุดท้ายยืนยันผ่าน 12/12 รายการ ภาพประกอบเป็นภาพระหว่างขั้นตอนทดสอบ ไม่ใช่หลักฐานว่าทุกขั้นตอนจบแล้ว ให้ยึดผลในรายงานร่วมกับขอบเขตด้านล่าง

ซอร์สสำเนาและ build ปัจจุบันอยู่ใน `.next/voices-browser/app-*` บน D: ทั้งหมด **ไม่มี junction ข้ามไดรฟ์ในโปรไฟล์ใหม่** ไม่เปลี่ยน `.next/dev` ของแอปเดิม รายงาน `harness.json` ระบุโฟลเดอร์ที่สร้าง ส่วน `stopped` เป็นเพียง marker หาก helper ได้รันการปิดเอง; Playwright บน Windows อาจยุติทั้ง tree โดย marker ไม่ได้อัปเดต จึงต้องตรวจพอร์ต/โปรเซสที่สร้างจริง ไม่อนุมานจาก marker อย่างเดียว

## ผลและข้อจำกัด

สถานะรอบสุดท้าย: แก้ข้อจำกัดการ build พร้อม browser ด้วยโปรไฟล์ใช้ RAM ต่ำ และรันผ่านครบแล้ว ยังไม่ใช่พร้อมเปิดใช้จริง

- รายงานเริ่ม `2026-09-24T09:24:34.554Z` (16:24 น. ประเทศไทย): ผ่าน **12/12 รายการ** ภายใน **47.26 วินาที** มี 6 scenarios × 2 browser profiles (desktop / Chromium จำลอง Pixel 7), ไม่มี skipped/flaky/unexpected และคำสั่งจบด้วย exit code 0
- เมื่อเริ่มรอบต่อ D: ว่างประมาณ 23 GiB แล้ว จึงไม่ต้องลบไฟล์ส่วนตัวหรือ cache ของแอปเดิมเพื่อเพิ่มพื้นที่
- Build แบบ production ของ snapshot 27 ไฟล์ผ่าน โดยยังตรวจ TypeScript และใช้หนึ่ง worker; ค่า RSS สูงสุดของ process compiler ที่สุ่มวัดในรอบสุดท้ายประมาณ **404 MiB** ไม่ใช่ยอดรวมทั้งเครื่อง และไม่ใช่ production build ของแอปทั้งโครงการ
- ตรวจตัวเก็บ dependency closure ผ่าน 3 ข้อ: ได้ routes/dynamic auth import ครบ, ปฏิเสธ `.env`/path traversal และ config สำเนาคง headers/การตรวจชนิดข้อมูล
- Scoped ESLint ของ config/browser tests/ตัวช่วยทดสอบที่แก้ผ่าน ไม่อ้างว่า lint ทั้งโครงการผ่าน
- ตรวจ TypeScript เฉพาะ `playwright.voices.config.ts`, `browser-tests/customer-voices.spec.ts` และ dependencies โดยใช้ compiler options เดิมผ่าน 0 diagnostics (RSS ประมาณ 228 MiB) การลองตรวจทั้งโครงการเพิ่มเติมด้วย heap จำกัด 768 MiB ยังจบด้วย out-of-memory จึงไม่อ้างว่าทั้งโครงการผ่านในรอบล่าสุด และไม่เพิ่มเพดานหน่วยความจำหรือวนรันชุดหนักต่อ
- หลังจบยืนยันพอร์ต localhost 3146/3147 ไม่ตอบสนอง และไม่พบโปรเซส helper/compiler/test workers ที่ติดตามไว้ แม้ `harness.json` ยังมี `stopped=false` เพราะ Playwright ยุติ process tree จากภายนอก; RAM ว่างประมาณ 1,081 MiB และ D: ว่างประมาณ 23.3 GiB ไม่ปิดแอปส่วนตัวของผู้ใช้
- ปรับการตรวจภาพ QR ให้เทียบพิกเซล PNG จริง ไม่เทียบ compressed bytes ซึ่งต่างกันระหว่าง browser canvas กับ Node แม้ภาพเดียวกัน
- ตรวจ cookie/Authorization ด้วย `request.allHeaders()` เพราะ `headers()` ของ Playwright ไม่แสดงบาง security headers และเพิ่ม cookie ควบคุมที่ต้องปรากฏใน navigation ก่อนตรวจว่า API ไม่ส่ง cookie นั้น
- กรณีลิงก์หมดอายุเปิดในหน้าใหม่ แยกจากกรณีเปลี่ยน fragment ในหน้าเดิมซึ่งแอปตั้งใจปิดกั้นเพื่อไม่ให้คำตอบข้าม Visit ไม่มีการแก้กติกาแอปเพื่อให้ test ผ่าน

### ประวัติรอบก่อน — ไม่ใช่สถานะล่าสุด

- รอบที่รันถึง browser มี 4 กรณีผ่าน: การตอบกลับสูญหายแล้วตรวจซ้ำด้วยคำขอเดิม และ Owner อ่านอย่างเดียว/ไม่มีบัญชีอ่านไม่ได้ ทั้ง desktop และ mobile
- กรณีที่เหลือพบ assertion จับ `role=alert` ของ Next route announcer ร่วมกับข้อความฟอร์ม และความคาดหวัง page Cache-Control ไม่ตรง `next dev` ขณะจบรอบเก่ายังยืนยันผลหลังแก้ครบทั้ง 12 กรณีไม่ได้; รอบล่าสุดยืนยันครบแล้วตามผลข้างต้น
- ระหว่างรันซ้ำเกิด `ENOSPC` บน D: จึงล้างเฉพาะสำเนาทดสอบของรอบนี้ แล้วปรับแยก build output ไป temporary directory; ต่อมาระบบรายงาน `Not enough memory resources` ตอนเริ่ม Chromium และหน้าเว็บ timeout จึงหยุดชุดหนัก ไม่วนรันซ้ำโดยไม่แก้เงื่อนไขเครื่อง
- TypeScript ทั้งโครงการและ Scoped ESLint ของชุดทดสอบผ่านในรอบเก่า ไม่มีการแก้ฟังก์ชันแอป/SQL เพื่อหลบข้อผิดพลาดทดสอบ
- ยืนยันตัวตรวจทรัพยากรหยุดก่อนสร้างสำเนาหรือเปิดเซิร์ฟเวอร์เมื่อ RAM ว่างไม่ถึงเกณฑ์ และตรวจว่า localhost พอร์ต 3146/3147 ไม่ตอบสนองหลังหยุด
- ตอนตรวจพบ RAM ว่างประมาณ 1.3 GiB และ D: เหลือประมาณ 90 MB; หลังล้างไฟล์ทดสอบที่สร้างเอง D: กลับมาเหลือประมาณ 320 MB ยังต่ำกว่าเกณฑ์

การติดตั้งชุดแยกช่วงแรกยังแก้ปัญหา font fixture และ Next/Webpack ที่ไม่แปลง TypeScript ภายใต้ node_modules / อ้าง entry ข้ามไดรฟ์ ข้อผิดพลาดเหล่านี้อยู่ใน harness ไม่ใช่หลักฐานว่ากติกา Customer Voices ผิด

รอบ dev เดิมเขียน page Cache-Control เป็น `no-cache, must-revalidate` แม้ตั้ง `no-store` ใน config; รอบปัจจุบันเป็น production-mode snapshot จึงตรวจ `no-store` ทั้ง page และ API ตามจริง แต่ยังต้องตรวจ HTTPS/CDN headers บน Vercel แยก

การทดสอบนี้ **ไม่ใช่** PostgreSQL/PostgREST จริง และไม่รับรอง signature/JWT, RLS, race condition หรือ transaction จาก HTTP fixture การตรวจ SQL ในฐานจำลอง native รอบก่อนเป็นหลักฐานคนละชั้น ไม่ให้นำยอดมาบวกรวมกัน

## ก่อนเปิดใช้จริงยังต้องทำ

- ระบุ Supabase และเว็บไซต์ staging ที่แยกจาก production: ผู้ใช้ยืนยันว่ามีโปรเจกต์ทดสอบแล้วและจะส่งชื่อมา ยังไม่ทราบเป้าหมาย จึงยังไม่เชื่อมต่อหรือรัน SQL ต้องตรวจยืนยันแบบอ่านอย่างเดียวก่อน และขออนุมัติขอบเขตติดตั้งแยก ร่าง SQL26 ยังมี guard และ ROLLBACK ไม่ใช่ไฟล์ให้คัดลอกรัน
- ตรวจสิทธิ์จริงครบ Sales เจ้าของงาน/Sales คนอื่น/Admin/Owner/anon และ broad legacy policies ผ่าน PostgREST รวมถึงการเรียก RPC โดยตรง
- กำหนดการจำกัดคำขอสาธารณะและการป้องกัน abuse ทั้ง Next API และ direct RPC; ตรวจไม่เก็บความลับ/คำตอบใน request logs, APM หรือ SQL parameter logs ยังไม่มี shared rate limiter/OTP/CAPTCHA
- ตรวจ production build/HTTPS/cache/CDN และสแกน QR จากกล้องมือถือจริง (Chrome Android และ Safari iPhone), refresh/back, หลายแท็บ และเครือข่ายขาด ผล Chromium จำลองไม่แทนขั้นตอนนี้
- สำรอง/ทบทวนข้อมูลเก่าและแผนย้อนกลับ แล้วขออนุมัติเปิดใช้จริงอีกครั้ง

ประวัติการคืนพื้นที่ในรอบเก่า: ล้างเฉพาะสำเนา/ไฟล์ทดสอบที่สร้างเอง 4 ชุดแรกคืนพื้นที่ประมาณ 300 MB และล้างชุดทดลองแยกไดรฟ์อีก 3 โฟลเดอร์หลังถอด junction ที่ตรวจปลายทางแล้วทั้งหมด ไม่ลบไฟล์แอป, node_modules ที่ใช้ร่วมกัน หรือ cache เดิมของผู้ใช้ ไฟล์ที่ล้างสร้างใหม่ได้จากซอร์ส รอบต่อปัจจุบัน D: มีพื้นที่เพียงพอแล้ว ไม่ได้ลบไฟล์เพิ่มหรือเปลี่ยนการตั้งค่าหน่วยความจำของ Windows
