# Sales V2 — เพิ่มโครงการให้ Lead เดิม

24 กันยายน 2569 — ต่อแผนงานก่อนจองเดิม ไม่ใช่หน้า UI จำลองหรือการเปิดระบบจริง

## ขอบเขตที่เชื่อม

Lead ส่วนกลาง → งานติดตามลูกค้า → **โครงการที่สนใจ / เพิ่มโครงการให้ลูกค้าคนเดิม** → เลือกโครงการและแปลงว่างที่เล็งไว้ (ไม่บังคับ) → ระบุเหตุผล → บันทึก → เปิดงานติดตาม/นัดหมายของโครงการนั้นในส่วนกลาง

- ใช้ customer เดิม ไม่สร้างหรือกรอกชื่อลูกค้า/เบอร์ซ้ำ รองรับทั้ง Lead ที่ยังไม่มีโครงการและผู้ที่มีโครงการอื่นอยู่แล้ว
- เพิ่มได้เฉพาะ Sales เจ้าของ Lead ส่วนกลางปัจจุบันกับ Admin; Sales อื่นและ Owner อ่านได้
- เจ้าของ interest ใหม่สืบทอดจากผู้ดูแล Lead ส่วนกลาง ไม่รับ owner จาก browser และไม่ถือว่า Admin ผู้บันทึกกลายเป็น Sales ผู้ดูแล การเปลี่ยนเจ้าของยังใช้ขั้นตอน Admin เดิม
- เลือกเฉพาะโครงการเปิดที่ลูกค้ายังไม่มี interest; ไม่สร้างซ้ำแม้รายการเดิมเป็น Lost และไม่เปิด Lost กลับเอง
- แปลงเป็นตัวเลือกค้นหาได้ ใช้รหัส TEXT จริง ตรวจว่าอยู่โครงการและยังว่างตอนบันทึก การเล็งไม่ล็อก/จองแปลง ลูกค้ารายอื่นยังจองแปลงนั้นได้ภายหลัง
- เก็บเหตุผล ผู้ทำ และเวลาเพิ่มโครงการจากเซิร์ฟเวอร์ใน audit เดิม ไม่แก้วันที่รับ Lead/เจ้าของส่วนกลาง/งานติดตาม/SLA/KPI หรือ interest เก่า ไม่สร้าง Visit หรือ sale สมมติ
- รายการ interest แบ่งหน้าละ 50; ตัวเลือกโครงการไม่เกิน 200 พร้อมบอกเมื่อมีมากกว่านั้น ไม่ถือว่าหนึ่งหน้าครอบคลุมทุกโครงการ
- ตรวจ revision และสิทธิ์ซ้ำในฐานเมื่อบันทึก ล็อก customer/สิทธิ์/โครงการ/แปลงตามลำดับที่เข้ากับการจอง เก็บคำขอเดิมเมื่อผลไม่แน่นอน ไม่ส่งซ้ำอัตโนมัติ ไม่ยกเลิกประวัติเดิมเพราะโหลดหน้าจอไม่สำเร็จ

## การปิดไว้และขอบเขตสิทธิ์

- API `/api/sales-crm/interests` และหน้า `/sales-crm/interests?customerId=…` ใช้บัญชีผู้เรียก ไม่มี service-role หรือ writer legacy สำรอง
- ต้องเปิดสวิตช์ server `SALES_CRM_V2_ENABLED`, `SALES_CRM_LEAD_WORK_ENABLED`, `SALES_CRM_LIFECYCLE_ENABLED`, `SALES_CRM_PROJECT_INTERESTS_ENABLED` ทั้งหมด และ capability `project_interests_v1` ฝั่งฐานต้องพร้อมด้วย **รอบนี้ไม่ได้เปิดค่าใด**
- SQL24 เพิ่ม `crm_settings.project_interests_enabled` ค่าเริ่ม false และ RPC อ่าน/เพิ่มพร้อมใบรับคำขอส่วนตัว ไม่เพิ่มตารางลูกค้าชุดใหม่หรือเปิดสิทธิ์เขียนตรง
- ร่าง `sql/sales/24_project_interests_draft.sql` ยังมี DESIGN ONLY ก่อน DDL และ ROLLBACK **ห้ามนำไปรันบน Supabase** ต้องเตรียม migration ที่ตรวจรับแล้วแยกต่างหาก
- ส่วนเลือกแปลงใช้ตัวอ่านแปลงเดิม การตรวจ RLS/legacy policies ทั้งระบบก่อนเปิดจริงยังเป็นงานค้าง ไม่ใช้ผล unit/mock/native ในเครื่องรับรองสิทธิ์ระบบจริง

## ยังไม่รวมในขั้นนี้

การเปลี่ยน/ลบโครงการเดิม การแก้แปลงที่เล็งใน interest เดิม การเปิด Lost กลับ การย้าย/คัดลอกงานติดตามเดิมให้ทุกโครงการ หรือการเพิ่ม SLA ซ้ำต่อโครงการ ไม่ได้ทำอัตโนมัติ

อัปเดตขั้นถัดมา 24 กันยายน: [SOP แยก Stage จากนัด/Visit](D:/buildtrack/buildtrack-mvp-main/docs/sales-v2-visit-sop.md) เชื่อมในเครื่องแล้ว โดยไม่ปิด Visit สำเร็จ ส่วน Customer Voices ต่อ Visit, QR, และช่องแปลงว่างในแบบเช็คอินยังต้องทำต่อ ตามข้อตกลงเดิม: คำถามเดิม คะแนน 8 ด้านต้องตอบ ข้อมูลรายได้/ส่วนตัวเพิ่มเติมไม่บังคับ ไม่มีคำตอบที่เลือกไว้ล่วงหน้า

ไม่อ่านข้อมูลลูกค้าจริง ไม่เชื่อม Supabase ไม่เปลี่ยน env ไม่ import ไม่ Deploy หรือเปิดแจ้งเตือนจริง

## ผลตรวจ

- ก่อนเชื่อมขั้นนี้ Vitest เดิมผ่าน 5,315 ข้อ / 137 ไฟล์ (หนึ่ง worker, 477.35 วินาที)
- หลังเชื่อม รันทวน 13 ไฟล์ที่เกี่ยวข้อง ผ่าน 291 ข้อ (รอบสุดท้าย 18.79 วินาที) รวม input/ผลอ่าน/สิทธิ์/feature gates/การกู้คำขอค้าง/หน้าจอ/ลิงก์จาก Lead เดิม/ตัวรันทดสอบ ไม่อ้างว่ารันทั้ง 137 ไฟล์ซ้ำหลังเชื่อม
- รอบ focused ก่อนหน้ามี 289 ผ่านและ 2 ไม่ผ่านจาก assertion หน้าจอ: ข้อความซ้ำสองตำแหน่งและการรอ element อยู่ภายใน async act ทำให้รอ render ไม่จบ แก้เฉพาะการเลือกข้อความและลำดับการรอใน test ไม่เพิ่ม timeout หรือผ่อนกฎธุรกิจ จากนั้นรัน 13 ไฟล์ใหม่ผ่านทั้งหมด ไม่มีคำเตือน act
- TypeScript ทั้งโครงการ `noEmit --incremental false` ผ่าน (heap 1152 MB เฉพาะ process; ไม่แก้ config)
- Scoped ESLint 24 ไฟล์ไม่มี error; มีคำเตือนหนึ่งจุดเรื่อง ref counter ใน cleanup จึงแยกฟังก์ชัน invalidate generation โดยรักษาพฤติกรรมเดิม แล้ว lint ไฟล์นั้นใหม่ผ่านโดยไม่มี warning และรันทวน focused suite อีกครั้ง `git diff --check` ผ่าน (มีเพียงข้อความ LF/CRLF)
- ฐาน PostgreSQL 17.11 ใหม่บน loopback ข้อมูลสมมติเท่านั้น: `--project-interests-only` รายงาน `runs/run-XYWnqX/report.json` ผ่าน **50 assertions + 5 กลุ่ม concurrency / 16 assertions** compile 22 ร่าง ตรวจ READ ONLY และ SQL/TypeScript projection parity
- รวมการอ่าน interest ที่เพิ่งเพิ่มผ่าน central search, lead work และ Visits จริงในฐานจำลอง ยืนยัน customer/interest/owner เดิมและไม่มีประวัติสร้างขึ้นเอง; ตรวจคำขอซ้ำ/เพิ่มโครงการเดียวกันชนกัน/เปลี่ยนเจ้าของ/ปิด Lost/จองแปลงชนการเล็ง
- hash ร่างต้นฉบับไม่เปลี่ยนระหว่างรัน, `stopped=true`, ไม่มี postmaster.pid ของฐานทดสอบ รอบก่อน `run-asdjF3` ผ่าน 47 + 16 assertions ก่อนเพิ่มการตรวจจุดเชื่อมสามข้อ และหยุดแล้วเช่นกัน

ยังไม่ได้ทดสอบ browser E2E/build/PostgREST/staging หรือรันชุด native แจ้งเตือนและความจุเดิมซ้ำ ผลนี้ไม่ใช่หลักฐานว่าระบบจริงพร้อมเปิด
