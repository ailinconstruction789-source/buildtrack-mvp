# ตรวจสิทธิ์ฝ่ายขายแบบอ่านอย่างเดียว

วันที่ 25 กันยายน 2569 — ต่อจากหน้าทดลองคืนสิทธิ์

อัปเดตต่อเนื่อง: เพิ่ม [คำสั่ง Admin รับรองคืนสิทธิ์ Sales เดิม](./account-security-access-restore.md) โดยแยก POST อีก endpoint และสวิตช์เริ่มปิด GET ในเอกสารนี้ยังอ่านอย่างเดียว ผลตรวจด้านล่างเป็นผลของขั้นอ่านข้อมูลเดิม

## สิ่งที่เพิ่มในโค้ด

- ลิงก์ “ตรวจสิทธิ์ฝ่ายขาย” จากหน้าจัดการผู้ใช้เดิม ไป `/admin/account-access`
- หน้ารายการค้นหาชื่อ กรองสถานะ และแบ่งหน้า 25 บัญชี แสดงรุ่น/เวลารับรองและหลักฐานพักสิทธิ์ล่าสุด
- ตัวอย่างหน้ารายการเดียวกันที่ `/dev/account-access/directory` เปิดด้วย `npm run dev` ใช้ข้อมูลสมมติ 5 บัญชี ไม่มี Supabase client ใน dependency ที่ทำงานฝั่งตัวอย่าง และปิด route นอก development
- GET `/api/admin/account-access` เท่านั้น ไม่เพิ่ม POST/PATCH/DELETE หรือปุ่มเปลี่ยนสิทธิ์
- ร่าง SQL `sql/security/account_access_read_draft.sql` ยังมี DESIGN ONLY + ROLLBACK **ไม่ใช่ migration พร้อมรัน ผู้ใช้ยังไม่ต้องนำไปรัน**

หน้าระบบจริงเริ่มปิด ต้องมีทั้ง `NEXT_PUBLIC_ACCOUNT_TRUSTED_AUTH_ENABLED=true` และ `ACCOUNT_ACCESS_READ_ENABLED=true` หลังผ่านการตรวจ/ติดตั้งฐานและอนุมัติเปิดแยกก่อน เอกสารนี้ไม่ใช่คำสั่งให้เปิดสวิตช์ รอบนี้ไม่เปลี่ยน `.env.local` หรือค่า Deploy

หน้า `/admin/account-access` ขณะปิดแสดง “เตรียมหน้าจอแล้ว ยังไม่เปิดอ่านข้อมูลจริง” และไม่ mount ตัวอ่าน ไม่ใส่ข้อมูลสมมติปนในหน้าจริง หากต้องการลองหน้าจอ ให้ใช้ URL ตัวอย่างข้างต้น

## ความหมายข้อมูล

แสดงเฉพาะบัญชีที่มี `reviewed_roles.role='Sales'` ไม่ใช่รายการพนักงานทั้งหมด และไม่ใช้บทบาทจาก metadata หรือรายชื่อเก่าเพื่อรับรองสิทธิ์อัตโนมัติ

| สถานะ | ความหมาย |
|---|---|
| เปิดใช้งาน | Auth พร้อม, canonical role enabled, CRM projection และรุ่นตรงกัน, ไม่มีหลักฐานพักสิทธิ์ในรุ่นปัจจุบัน/ใหม่กว่า |
| รอ Admin รับรองใหม่ | Auth พร้อม, canonical role enabled, CRM ไม่ active และมีหลักฐานพักสิทธิ์ที่ยังไม่ได้รับรองข้ามรุ่น |
| บัญชี Auth ใช้งานไม่ได้ | ถูกแบน / ปิด / anonymous / ไม่พบบัญชี ตามข้อมูลที่ตรวจขณะอ่าน |
| ปิดสิทธิ์ตามรายการรับรอง | canonical role disabled ไม่ตีความว่าแค่ปลดแบนแล้วควรคืนสิทธิ์ |
| ต้องตรวจความสอดคล้องของสิทธิ์ | เงื่อนไขอื่นไม่ลงตัว เช่น projection ถูกพักแต่ไม่มีหลักฐาน Auth ที่อธิบายรุ่นนี้ ห้ามเดาว่าต้องเปิดใหม่ |

“เหตุพักสิทธิ์ล่าสุด” เป็นรหัสเหตุจาก Auth (แบน/ปิด/anonymous) และเวลาที่ระบบบันทึก ไม่ใช่คำอธิบายที่ผู้แบนกรอก และไม่ใช่ประวัติ Auth/การรับรองทั้งหมด การไม่พบหลักฐานไม่ได้ยืนยันว่าไม่เคยถูกแบน

ไม่ส่งอีเมล PIN/password/session/token/metadata หรือข้อความอ้างอิงส่วนตัวจากการรับรองออกมา มีเฉพาะรายการข้อมูลที่อนุญาตไว้ โดยตรวจรูปแบบทั้งฝั่ง server และ client

## ขอบเขตสิทธิ์

- API ตรวจ bearer กับ Auth แล้วอ่าน `app_current_actor`; ต้องเป็น Admin และ `canManageAccounts=true`
- SQL reader ตรวจ canonical Admin, reviewed_admins, Auth account และ session อีกครั้ง แม้เรียก RPC โดยตรง ไม่ให้สิทธิ์จาก metadata หรือป้ายบทบาทเก่า
- ส่วนอ่านข้อมูลภายในใช้ SECURITY DEFINER เฉพาะเพื่ออ่านตารางส่วนตัว พร้อม search_path ว่างและสิทธิ์ EXECUTE จำกัด; public wrapper ใช้ INVOKER ไม่ให้สิทธิ์อ่านตารางส่วนตัวโดยตรง
- SQL เป็น STABLE และไม่มีการเขียน ทำงานใน READ ONLY transaction ได้ การอ่านที่เริ่มก่อนการถอนสิทธิ์ commit อาจเห็น snapshot เดิม ไม่อ้างว่าล้างข้อมูลที่ผู้ใช้เคยได้รับไปแล้วได้
- Client ตรวจเซสชันก่อน/หลังคำขอและหลังอ่านคำตอบ ล้างข้อมูลที่เห็นเมื่อ Auth เปลี่ยน; ผลเก่าที่มาช้าจะไม่กลับมาแสดง ตรวจใหม่เมื่อกลับมาหน้าและทุก 60 วินาที ไม่มี browser persistence
- ไม่ใช้หน้าทดลองเป็นหลักฐานสิทธิ์ ไม่ทำ sign-out/ban/unban/review/update presence จากหน้าใหม่นี้

ยึดหลักสิทธิ์ขั้นต่ำและการถอน EXECUTE ที่ได้โดยปริยายตาม [Supabase Database Functions](https://supabase.com/docs/guides/database/functions) และแนวทาง Supabase/Postgres ที่ใช้ในงานนี้ แต่ผลทดสอบ local ไม่แทนการตรวจสิทธิ์จริงของโครงการ

## ยังเหลือก่อนเปิดข้อมูลจริง/เปิดสิทธิ์จริง

ต้องตรวจโครงสร้างและ grants ของ Supabase แยก, ทดสอบ Auth/PostgREST จริง, จัด migration ที่ได้รับอนุมัติ และตรวจคู่บัญชีที่รับรองแล้วก่อนเปิดโหมดจริง ส่วนคำสั่งรับรองได้เตรียมต่อในเอกสารด้านบนโดยยังปิดอยู่ ไม่เปิด operator SQL ทั่วไปให้ browser เรียกตรง ๆ

ไม่มีการอ่าน/เปลี่ยนบัญชีหรือลูกค้าจริง, ติดตั้ง SQL จริง, Deploy, เปลี่ยน PIN/สิทธิ์/feature flags หรือเปิด Cron ในรอบนี้ หน้าอื่นของแอปยังใช้ค่าการเชื่อมต่อเดิมตามปกติ
