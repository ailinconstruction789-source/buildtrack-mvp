# รายงานจองที่เชื่อม Lead ส่วนกลาง

23 กันยายน 2569 — เตรียมโค้ดและ SQL20 ในเครื่องเท่านั้น ไม่รัน Supabase ไม่อ่านลูกค้าจริง ไม่เปลี่ยน env/สวิตช์ ไม่ Deploy และไม่เปิดแจ้งเตือน

## สิ่งที่ต่อแล้ว

- `/sales-crm/reports` และลิงก์จาก Lead ส่วนกลาง/รายชื่อจองโครงการ อ่านยอดรวมจาก `sales → lead_project_interests → sales_customers` ใน snapshot เดียว ไม่ดึงทีละ50รายการมาบวกและไม่ใช้การจองแรกของลูกค้า
- เลือกทุกโครงการ (รวมลูกค้าที่ยังไม่เลือกโครงการ) หรือรายโครงการ รวมโครงการปิดที่ยังมีประวัติ ลูกค้าบริษัทนับตาม customer ID ไม่รวมคนจากชื่อ/เบอร์; ความสนใจนับแยกต่อโครงการ
- จองทั้งหมดรวมทุกรอบ, ยกเลิกแยก, จองสุทธิ = ทั้งหมด − ยกเลิก; โอน/ส่งมอบเป็นส่วนหนึ่งของจองสุทธิ ไม่บวกเป็นบ้านอีกหลัง การปฏิเสธกู้ที่ยังไม่ยกเลิกไม่เป็น cancellation
- เลือกช่วง **วัน Lead เดิมตามเวลาไทย** รวมวันต้น–ปลาย แล้วอ่านผลจองปัจจุบันของลูกค้ากลุ่มนั้น ไม่ใช่ยอดจองที่เกิดในเดือน ไม่ใช่ snapshot ย้อนหลัง ณ วันสิ้นสุด และไม่ตัดสินวิธีหักการยกเลิกข้ามเดือนสำหรับ KPI
- วันที่ Lead ไม่ทราบ: ดูได้เมื่อเลือกทุกวัน; กรองช่วงวันจะไม่เดาวันเข้าให้ พร้อมจำนวนที่ถูกตัดออก วันจอง/ยกเลิกไม่ทราบแยกจำนวน ไม่อนุมานจาก `created_at` หรือวันที่นำเข้า
- ราคาขายสุทธิที่ทราบรวมด้วยเลขทศนิยมในฐาน ส่งเป็นข้อความทศนิยมที่ตรง ไม่ผ่าน JS Number จึงไม่ทำสตางค์หาย; ราคาไม่ทราบแยกจำนวน ถ้าไม่ทราบทุกรายการจะแสดง “ไม่ทราบมูลค่า” ไม่แสดงยอดรวมเป็นศูนย์ ราคา0ที่มีหลักฐานคงเป็น0
- รายงานรวมไม่ส่งชื่อลูกค้า เบอร์โทร รายได้ หรือข้อมูลบุคคล; ไม่ให้เครดิตแก่เจ้าของปัจจุบันแทน Sales ที่ทำงานจริงย้อนหลัง ไม่ให้คะแนน KPI/HR

## การเชื่อมเมนูเก่า โดยยังไม่เปิดสวิตช์

ใช้โหมดเดิมจาก `SalesWorkspaceModeProvider` โดยไม่เพิ่มสวิตช์ใหม่และไม่เปลี่ยนค่าจริง:

| ทางเข้า | เมื่ออนุมัติใช้โหมดส่วนกลางในอนาคต |
|---|---|
| Dashboard ฝ่ายขาย / รายงานสรุปยอด | รายงานจองส่วนกลางข้างต้น ไม่ใช่ชุดรายงานทุกมิติเดิม |
| ตารางสรุปรายแปลง | รายการจองทุกสถานะจากตัวอ่าน19; ยังไม่ใช่บัญชีแปลงว่าง/ราคาประเมิน |
| `/owner` ซึ่งเดิมใช้ตัวเลขตัวอย่าง | รายงานจองส่วนกลาง; ไม่ใช้ KPI/forecast ตัวอย่าง |
| ผลงาน Sales รายบุคคล / Business Insights | แจ้งขอบเขตที่ยังไม่พร้อมและลิงก์รายงานรวม ไม่เอายอดทั่วไปแสดงเป็นคะแนนบุคคล |
| Dashboard ที่ถูกซ่อนไว้ในหน้าหลัก | ไม่ mount ตัวอ่านเก่าหรือตัวอ่านใหม่ในโหมดส่วนกลางจนเปิดหน้านั้น |

โหมด legacy ยังส่ง props และเปิดโมดูลเดิมเหมือนก่อน โหมด blocked ไม่ fallback กลับรายงานเก่า Root OwnerAnalyticsDashboard ด้านก่อสร้างคนละไฟล์ไม่ถูกแก้

ตัวครอบเมนูไม่ใช่ RLS/การปิดผู้เขียนเก่า ทุกสวิตช์ยังคงเดิมและห้ามเปิด `SALES_CRM_PROJECT_WORKSPACE_ENABLED` เพื่อถือว่า cutover พร้อม รายงานเก่าถูกเก็บไว้ ไม่ลบไฟล์หรือข้อมูลใด

## ความพร้อมและความปลอดภัย

GET ใช้ JWT ผู้เรียก ตรวจบทบาทจากฐานและ capability `sales_reports_v1` แบบตรงรุ่น ไม่มี service-role key หรือ direct-table/legacy fallback ส่ง `no-store` และตรวจ scope/actor/ความสัมพันธ์ยอดรวมทั้ง server และ client

SQL20 มีตัวหยุด DESIGN ONLY ก่อนสร้างฟังก์ชัน และปิดท้าย ROLLBACK **ยังไม่ใช่ไฟล์ติดตั้งให้รันบน Supabase** ฟังก์ชันสองตัวเป็น STABLE SECURITY DEFINER, search_path คงที่, authenticated เท่านั้น ไม่เขียน audit/receipt/งาน/สต็อกหรือส่งแจ้งเตือน

ก่อนกรองช่วงวัน ตรวจ mapping การจอง ลูกค้า ความสนใจ แปลง และหลักฐานผิดรูป หากตรวจไม่ผ่านให้หยุดพร้อมแจ้ง Admin ไม่ซ่อนปัญหาด้วยตัวกรอง/แบ่งหน้าและไม่แสดงยอด0แทนข้อผิดพลาด ข้อมูลเก่าที่ไม่ทราบเก็บ null; ค่าที่ขัดแย้ง เช่น NaN/ราคาติดลบ ไม่แปลงเป็น0

Legacy Lead ทุกแถวต้องมี `crm_legacy_lead_links` ที่อ้าง customer ปัจจุบันถูกต้อง แม้ยังไม่เคยจอง ถ้าขาดการเชื่อมนี้จะหยุด **ทุกขอบเขตรายงาน** อย่างระมัดระวัง เพราะยังระบุ denominator ของโครงการไม่ได้ ไม่ใช้โทรศัพท์หรือ `legacy_source_lead_id` แทน mapping ที่ตรวจรับ กรณีรวมลูกค้าแล้วยังไม่ได้ย้ายความสนใจแม้ไม่มี sale จะหยุดรายงานโครงการนั้นและรายงานรวมก่อนกรองวัน

## การตรวจสอบ

ใช้ mock และฐานสมมติแยกเท่านั้น ไม่ใช่การรับรอง production

- Vitest ทั้งแอป 4,905 tests / 119 files ผ่าน โดยรันหนึ่ง worker; รวมการคง legacy เมื่อสวิตช์ปิด, ไม่ mount dashboard ที่ซ่อนในโหมดใหม่, ขอบเขตบทบาท, วันที่, ความสอดคล้องยอดรวม, ผลตอบกลับสลับลำดับ และการไม่แสดงศูนย์เมื่ออ่านไม่ได้
- ESLint เฉพาะไฟล์ใหม่/จุดเชื่อมผ่าน และ `git diff --check` ผ่าน ไม่แก้โค้ดเดิมนอกขอบเขตเพื่อเก็บ lint ทั้งโครงการ
- TypeScript `noEmit` ทั้งโครงการผ่าน หลังแก้ชนิดข้อมูล URL ในไฟล์ทดสอบใหม่ ไม่เปลี่ยนกฎธุรกิจเพื่อให้ตรวจผ่าน

- PostgreSQL แยกโหมด `sales-reports-only`: 78 assertions ผ่าน รวม transaction แบบ READ ONLY, business snapshot ไม่เปลี่ยน, cohort ขอบวันไทย/ปีอธิกสุรทิน, 68 sale rounds ในโครงการ, cancel/rebook/multi-plot, legacy mapping ของ Lead ที่ยังไม่จอง และการรวมเงิน0/ไม่ทราบ
- SQL/TypeScript projection parity ผ่าน; ร่าง base/04–20 รวม18ไฟล์ compile และ hash ไม่เปลี่ยนจากการทดสอบ รายงาน `node_modules/.cache/buildtrack-sales-runtime/runs/run-xdN2Qk/report.json` ระบุ `passed`, `projectionParity: true`, `stopped: true`
- รอบนี้ไม่ได้รัน concurrency/ความจุของงานแจ้งเตือนซ้ำทั้งชุด ไม่ทดสอบบัญชีจริง/PostgREST/Supabase และยังไม่รับรอง production build/E2E
