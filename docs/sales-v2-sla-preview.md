# ตรวจแผน SLA ติดต่อครั้งแรก — เชื่อมในโค้ดแบบจำลอง ยังไม่เปิดใช้

สถานะ 17 กันยายน 2569: ต่อแหล่งข้อมูลเวรและหลักฐานงานเข้าตัวคำนวณฝั่ง Server พร้อมหน้า Admin ตรวจผลแบบอ่านอย่างเดียวแล้ว **ยังไม่รัน SQL/RPC ไม่อ่านฐานจริง ไม่เปิดฟีเจอร์ ไม่บันทึกกำหนด และไม่ส่งแจ้งเตือน** ไม่มี SQL ติดตั้งให้ผู้ใช้นำไปรัน

## 1. กติกาที่ผู้ใช้ยืนยันและนำมาคำนวณ

กำหนดบริการลูกค้ายังคง 24 ชั่วโมงจริงนับจาก Lead เข้าเดิม แยกจากกำหนดรับผิดชอบของ Sales:

| สถานการณ์ | กำหนด Sales ที่ใช้ในตัวอย่าง |
|---|---|
| Lead เข้านอกช่วงทำงานจริง | 120 นาทีทำงานจากช่วงทำงานถัดจากเวลา Lead เข้า |
| Lead เข้าในเวร และกำหนดบริการอยู่ในช่วงทำงานจริง | ใช้กำหนดบริการ 24 ชั่วโมงเดิม |
| Lead เข้าในเวร แต่กำหนดบริการตกช่วงพัก/ลา/นอกเวร | 120 นาทีทำงานจากช่วงทำงานถัดจากกำหนดบริการ |

นับเฉพาะเวรที่ Admin ยืนยันครบแล้ว หักพัก/ลาซ้อนกันโดยไม่หักซ้ำ และนับข้ามช่วงพักหรือหลายวันได้ ไม่เดาวันหยุด เวลาเริ่มเวร หรือเวลาลา เวลาเริ่มช่วงนับว่าอยู่ในเวร ส่วนเวลาสิ้นสุดไม่นับรวม เช่น สิ้นเวร 18:00 คืออยู่นอกเวรแล้ว

เตือนล่วงหน้า **30 นาที** ตามข้อตกลงก่อนหน้า และแจ้งเฉพาะขณะอยู่ในเวลาทำงานจริง กำหนดตรงเวลาเป๊ะยังเป็นใกล้ครบกำหนด; เกินแม้ 1 microsecond จึงเป็นเกินกำหนด ใช้ `service_due_at` เป็นบริบทลูกค้าเท่านั้น ไม่ใช้ตัดคะแนน Sales

กติกาเข้าในเวรได้รับการยืนยันในรอบนี้ ไม่ต้องถามซ้ำ ส่วนเปลี่ยนเจ้าของและลูกค้าขอนัดภายหลังยังพักให้ตรวจหลักฐาน ไม่คำนวณสูตรใหม่ให้อัตโนมัติ และไม่มีหน้ารับรองข้อยกเว้นหรือเปลี่ยนกำหนดในรอบนี้

## 2. การเชื่อมข้อมูลที่เตรียมแล้ว

`GET /api/sales-crm/sla-preview?page=0` → ตรวจ token/บทบาท Admin → อ่าน snapshot งาน/หลักฐาน/เวรล่าสุด → ตรวจข้อมูล → คำนวณบริการเทียบกับกำหนดเดิม → หักพัก/ลา → คำนวณกำหนด Sales → จำลองเงื่อนไขแจ้ง → ส่งเฉพาะผลที่จำเป็นให้หน้า Admin

หน้า `/sales-crm/sla-preview` มีลิงก์จาก Lead ส่วนกลางเฉพาะ Admin เมื่อเปิดครบทุกสวิตช์ และซ่อนลิงก์ขณะฟอร์มรับ Lead เปิดอยู่ แสดงครั้งละ 20 งาน พร้อมวันบริการเดิม วัน Sales ที่คำนวณ เหตุผล และรุ่นเวร จำนวนสรุปเป็น **เฉพาะหน้านั้น** ไม่ใช่ KPI รวมทั้งบริษัท

รองรับเฉพาะงาน `first_contact` ส่วนกลางที่เปิดอยู่และไม่ได้มาจากกิจกรรมอื่น ไม่รวม Follow-up/Hot หลัง Visit/งานโครงการ ไม่สร้างภาระซ้ำ ไม่เพิ่มลูกค้า หรือเปิดงานใหม่จากการดูหน้า

แสดงผล 3 กลุ่ม: เข้าเงื่อนไขแจ้งแบบจำลอง, ยังไม่ถึงเวลา/นอกเวลางาน, และพักรอตรวจหลักฐาน ไม่มีปุ่มส่ง อนุมัติ บันทึกกำหนด ปิดงาน หรืออ่านแจ้งเตือนให้จากหน้านี้ ไม่มี polling

## 3. หลักฐานที่ต้องผ่านและเหตุที่พัก

- เป็นข้อมูลใหม่ `live` มีหลักฐานสร้าง Lead เดียวที่ตรงลูกค้า ผู้สร้าง เจ้าของ และเวลาเริ่มงาน; ข้อมูลเก่าไม่ถูกอนุมานว่าพร้อม
- ผู้ดูแลงานตรงผู้ดูแลปัจจุบัน เป็น Sales ที่ active มีประวัติยืนยันว่าไม่เปลี่ยนคน ไม่ใช้การย้ายไปแล้วกลับมาเป็นหลักฐานว่าไม่เคยย้าย
- วันเริ่มงานตรงวัน Lead เดิม กำหนดบริการที่เก็บไว้ตรง 24 ชั่วโมงตามหลักฐานของงาน เวลาย้อนแย้ง/อนาคตหรือค่าตั้งไม่ตรงนโยบายที่รองรับต้องพัก ไม่เขียนแก้เดิม
- มีหัวเวรและรุ่นปัจจุบันที่เผยแพร่ก่อนเวลาอ่าน มีเวรครบสำหรับการคำนวณ ช่วงเวรไม่ซ้อน เจ้าของทุกช่วงตรงกัน รวมแถวทุกช่วงของรุ่น ไม่ตัดแถวผิดเจ้าของทิ้งเงียบ ๆ
- Lead ปิด/ถูกรวม, หลักฐานถูก correction, pending owner review, ลูกค้าขอเลื่อน, มีข้อยกเว้น, หรือมี metadata ยกเลิกที่ขัดกับงานเปิด ต้องพักให้ตรวจ
- หากพบหลักฐานติดต่อหรือ metadata จบงาน ทั้งที่งานยังเปิด จะพัก ไม่ส่งเตือนติดต่อครั้งแรกต่อและไม่ปิดงานเอง กติกาเลือกหลักฐานเพื่อจบ SLA จะต่อแยก

แถวที่พักยังอยู่ในคิวพร้อมเหตุผล ไม่ถูกให้ 0% หรือ 100% และไม่แสดงกำหนด Sales ที่คำนวณค้างไว้ ข้อมูลเวร/หลักฐานที่ผิดรูปแบบจนอ่านอย่างปลอดภัยไม่ได้จะทำให้คำขอไม่พร้อม แยกจากคิวว่าง

## 4. สิทธิ์และความเข้ากันได้

- Admin เท่านั้นทั้งหน้า API และ RPC ไม่เชื่อ `user_metadata` ไม่ใช้ service-role ไม่ให้ Sales/Owner เห็นคิวหรือเวรพนักงานคนอื่น
- API รับเพียงเลขหน้า ไม่มี POST หรือ payload ให้ browser ส่งเจ้าของ เวร เวลา หรือผลคำนวณมาเป็นหลักฐาน
- ใช้ตารางเดิมทั้งหมด ร่าง 08 เพิ่มเพียงสวิตช์เริ่มปิดและ RPC อ่าน `crm_v2_sla_preview_capabilities` / `crm_v2_sla_preview_source` สัญญา `first_contact_preview_v1` ไม่มีตารางงาน/เวร/แจ้งเตือนซ้ำ
- ข้อมูลจาก RPC จำกัดหน้าละ 20 งาน เวรไม่เกิน 400 ช่วงต่อรุ่น ถ้าเกินจะไม่ตัดให้ดูเหมือนครบ อ่านทั้งหมดด้วย snapshot เดียวโดยไม่ล็อกเพื่อเขียน ไม่เปลี่ยน last_seen/read_at
- รายละเอียดเวรและธงหลักฐานใช้เฉพาะฝั่ง Server ผลให้หน้า Adminไม่มีเบอร์ รายได้ เหตุผลลา ข้อความกิจกรรม raw snapshot รหัสกันซ้ำ หรือคำสั่งพร้อมเขียน
- ล้างข้อมูลเมื่อออกจากระบบ/เปลี่ยนบัญชี ตรวจบัญชีทั้งก่อนและหลังอ่าน response body ไม่รับผลคำขอคนเดิมกลับมาแสดง และให้ตรวจบัญชีใหม่อย่างชัดเจน
- ต้องเปิดสวิตช์ Server เดิมทั้ง 5 และ `SALES_CRM_SLA_PREVIEW_ENABLED` พร้อมสวิตช์ฐานเดิมทั้ง 5 และ `sla_preview_enabled` การเปิดจริงต้องอยู่ในแผน build/deploy ไม่เปลี่ยน env ในรอบนี้

ร่าง [08_sla_preview_draft.sql](D:/buildtrack/buildtrack-mvp-main/sql/sales/08_sla_preview_draft.sql) มีตัวหยุดก่อน DDL และ ROLLBACK **ห้ามถอดตัวหยุดแล้วรันเอง** ไม่แก้ SQL foundation/04–07 หรือสิทธิ์ฐานจริง

## 5. สิ่งที่ยังไม่ได้ทำและขั้นถัดไป

ผล `would_notify` เป็นผลจำลองเท่านั้น ยังไม่ได้ตรวจแจ้งเตือนเดิมเพื่อกันซ้ำ ไม่ได้บันทึก `staff_due_at`/`notify_at`/`notificationBinding` ไม่เปลี่ยนกำหนดบริการ ไม่ตั้ง scheduler ไม่ส่งจริง และไม่คิด KPI

อัปเดตรอบต่อเนื่อง: เตรียม [คำสั่งหลังบ้านประมวลผลติดต่อครั้งแรก](D:/buildtrack/buildtrack-mvp-main/docs/sales-v2-first-contact-processing.md) และร่าง 09 แยกจากหน้าอ่านนี้แล้ว โดยคำนวณ/ตรวจหลักฐานใหม่ในธุรกรรม ไม่รับผลจากหน้านี้เป็น commit token กันซ้ำ ไม่คืนชีพรายการ withdrawn และรักษาประวัติรุ่นเวร ยังไม่มีปุ่มเรียก ไม่มีการส่งจริง และยังไม่รัน SQL ต้องทดสอบ PostgreSQL/RLS/concurrency และเทียบตัวคำนวณในฐานแยก ก่อนออก SQL ติดตั้งที่ผู้ใช้ตรวจและรันเอง

งาน Follow-up/Hot และการรับรองข้อยกเว้นต้องมีเกณฑ์แยก ไม่ขยายกติกาติดต่อครั้งแรกไปใช้แทนโดยอัตโนมัติ ผลตรวจในเครื่องและการรักษางานเดิมอยู่ใน [แผน rollout](D:/buildtrack/buildtrack-mvp-main/docs/sales-v2-compatibility-and-rollout.md)
