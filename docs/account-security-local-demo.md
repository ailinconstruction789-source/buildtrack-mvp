# ทดลองคืนสิทธิ์ฝ่ายขายผ่าน npm run dev

วันที่ 25 กันยายน 2569 — หน้าทดลองในเครื่องต่อจากร่าง [Auth revocation](./account-security-auth-revocation.md)

ต่อเนื่อง: เพิ่ม [หน้าตรวจสิทธิ์ฝ่ายขายแบบอ่านอย่างเดียว](./account-security-access-reader.md) และตัวอย่างหน้ารายการที่ `/dev/account-access/directory` ใช้ส่วนแสดงผลเดียวกับหน้าจริง แต่ไม่เชื่อม Supabase หน้าทดลองเดิมมีลิงก์ไปแล้ว

ล่าสุด: หน้ารายการตัวอย่างข้างต้นลอง [รับรองคืนสิทธิ์ Sales ตัวอย่าง B](./account-security-access-restore.md) ด้วยแบบฟอร์มเดียวกับที่เตรียมให้ Admin ได้แล้ว ยังไม่เชื่อมข้อมูลจริง รีเฟรชแล้วเริ่มใหม่

## เปิดทดลอง

1. เปิด terminal ใน `D:\buildtrack\buildtrack-mvp-main` แล้วรัน `npm run dev`
2. เปิด `http://localhost:3000/dev/account-access` หากแอปแจ้งพอร์ตอื่น ให้ใช้พอร์ตที่แอปแสดง
3. เปิด URL นี้โดยตรงได้ ไม่ต้องล็อกอิน ไม่ต้องตั้ง feature flag หรือรัน SQL

หน้านี้ใช้บัญชีสมมติและ state ในหน่วยความจำเท่านั้น ไม่มี Supabase client, API request หรือ local/session storage ในส่วนทดลอง รีเฟรชแล้วเริ่มใหม่ มีป้ายเตือนตลอดหน้าและไม่เปิดเมื่อ `NODE_ENV` ไม่ใช่ `development`

**ข้อจำกัดสำคัญ:** การใช้ `npm run dev` ไม่ได้ทำให้แอปทั้งระบบแยกจากฐานจริง หน้าเดิมอื่น ๆ ยังอาจใช้ Supabase ที่ตั้งใน `.env.local` ได้ การไม่เชื่อมต่อฐานข้อมูลในเอกสารนี้หมายถึงหน้า `/dev/account-access` เท่านั้น ไม่ได้ปิดหรือเปลี่ยนการเชื่อมต่อของระบบเดิม

## สิ่งที่ลองได้

- Sales ตัวอย่าง A: มีสิทธิ์อยู่ → แบน → พักสิทธิ์ → ปลดแบน → ยังพักอยู่ → Admin รับรองใหม่แล้วจึงเปิดสิทธิ์
- Sales ตัวอย่าง B: เริ่มจากถูกแบน ต้องปลดแบนก่อนรับรอง
- Sales ตัวอย่าง C: เริ่มจากปลดแบนแล้วแต่ยังรอรับรอง
- เปลี่ยนมุมมองเป็น Owner / Sales เพื่อดูว่ารับรองไม่ได้ การเปลี่ยนมุมมองนี้เป็นตัวควบคุมตัวอย่าง ไม่ใช่ระบบตรวจตัวบุคคลจริง
- Admin ต้องกรอกเหตุผล หลักฐานอ้างอิงสมมติ และยืนยันการตรวจ ก่อนกดรับรอง แสดงรุ่นสิทธิ์ใหม่และรายการที่ลองในหน้านี้
- ออกจากระบบตามปกติทำให้เซสชันตัวอย่างใช้ CRM ไม่ได้ แต่ไม่พักสิทธิ์เจ้าของงาน ไม่หยุดงานลูกค้าจากเหตุ sign-out เพียงอย่างเดียว
- ตัวชี้ผลต่องานบอกความพร้อมของเจ้าของ Lead / QR / งานแจ้งเตือนเท่านั้น ไม่สร้าง Lead, QR, Visit หรือส่งแจ้งเตือนจริง

ไม่มีปุ่มลบบัญชีจริงหรือแก้ PIN ไม่ใช้ชื่อพนักงาน/ลูกค้าจริง ไม่เก็บข้อมูลที่กรอกถาวร และไม่ได้แทนที่หน้าจัดการผู้ใช้เดิม

- Vitest **88/88 ผ่าน** จาก 7 ไฟล์: ชุดใหม่ 3 ไฟล์และ regression ล็อกอิน/รายชื่อ/บทบาทที่เกี่ยวข้อง 4 ไฟล์ ไม่ใช่การรันทุกชุดของ repository
- TypeScript เฉพาะโค้ดใหม่: **0 diagnostics**; ESLint ทั้ง 6 ไฟล์ใหม่ผ่าน
- เปิด Next development server ด้วย `npm run dev -- --webpack --hostname 127.0.0.1 --port 3148` สำเร็จ หน้า HTTP 200
- Browser smoke ผ่านที่ 1440×1000 และ 390×844: แบน–ปลดแบน–รับรอง, Owner รับรองไม่ได้, logout ไม่หยุด ownership, refresh เริ่มใหม่, ไม่มีแนวนอนล้น
- ช่วง browser smoke ปิดกั้น origin ภายนอกและ API: **0 external requests, 0 API requests, 0 page errors**, local/session storage ว่าง
- การรันทดสอบ override ค่าการเชื่อมต่อเป็น loopback/คีย์สมมติเฉพาะ process และใช้ฟอนต์ offline ไม่แก้ `.env.local` หรือการตั้งค่าของผู้ใช้ เซิร์ฟเวอร์ทดสอบที่พอร์ต 3148 ปิดแล้ว
- ตรวจภาพหน้าจอ desktop/mobile แล้วที่ `node_modules/.cache/account-access-demo/desktop.png` และ `mobile.png` ใช้ฟอนต์ fallback ของเครื่องในรอบทดสอบ

ไม่ได้รัน production build หรือ Supabase Auth จริง การปิด route นอก development ตรวจด้วย unit test ไม่ใช่ผลจาก deployed URL; การปิดกรณีแบน/รับรองในหน้านี้เป็นตัวอย่าง UI ไม่ใช่หลักฐาน RLS/JWT/สิทธิ์บัญชีจริง

## ยังไม่เปิดใช้จริง

ไม่มี SQL/migration/deploy/feature flag ใหม่ในรอบนี้ และไม่แก้ Supabase จริง ร่างความปลอดภัยเดิมยังอยู่ในสถานะเดิม การทดสอบ Auth/PostgREST และการต่อช่องรับรองที่ปลอดภัยยังจำเป็นก่อนนำไปเปลี่ยนสิทธิ์บัญชีจริง ไม่ควรเอา `lib/dev/accountAccessDemo.ts` ไปใช้ตัดสินสิทธิ์คำขอของแอป
