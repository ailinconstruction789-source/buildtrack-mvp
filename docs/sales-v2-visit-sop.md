# Sales V2 — SOP เตรียมบ้าน / พาชม / ปิดบ้าน

อัปเดตขั้นถัดมา: เตรียม [Customer Voices ต่อ Visit และ QR](D:/buildtrack/buildtrack-mvp-main/docs/sales-v2-customer-voices.md) ในเครื่องแล้ว ข้อความ “ยังไม่รวม Customer Voices/QR” ด้านล่างเป็นขอบเขตของรอบ SOP เดิม SOP ไม่ได้เปลี่ยนให้เป็นหลักฐานแทนแบบสอบถาม และยังไม่เปิดระบบจริง

24 กันยายน 2569 — ต่อจากการเพิ่มโครงการให้ Lead เดิม ทำและตรวจในเครื่องเท่านั้น ยังไม่เปิดใช้งานจริง

## ทางเข้ากับงานเดิม

Lead ส่วนกลาง → โครงการที่สนใจ → นัดหมาย / เข้าชม → SOP ของนัดหรือ Visit นั้น

เริ่มเตรียมบ้านจากนัดล่วงหน้าได้ เมื่อเช็คอินแล้ว ทางเข้าจาก Visit จะใช้ SOP เดิมของนัด ไม่สร้างซ้ำ ส่วน Walk-in ที่ไม่มีนัดเริ่มจาก Visit จริงได้ มีหนึ่ง SOP และหนึ่งบ้านที่พาชมต่อครั้งตามโครงสร้างเดิม บ้านที่พาชมกับแปลงที่เล็งอาจคนละแปลงกัน

รายการบ้านพาชมค้นหาได้จากบ้านในโครงการเดียวกันทุกสถานะ ไม่ใช่ตัวเลือกแปลงว่างสำหรับจอง ไม่ล็อกสต็อกหรือเปลี่ยนแปลงที่สนใจ ตัวเลือกจำกัด 200 พร้อมแจ้งเมื่อมีมากกว่านั้น ประวัติเหตุการณ์แบ่งหน้า 50 รายการ

## ขั้นตอน

1. เริ่ม SOP: ระบุบ้านที่จะพาชม เวลาที่ทำจริง และเหตุผล ผู้ทำเป็น Sales เจ้าของความสนใจโครงการปัจจุบัน ไม่เลือกบัญชีอื่นแทน
2. Stage A: 16 รายการเตรียมบ้าน/รถ/ข้อมูลตามรายการเดิม บันทึกบางส่วนแล้วกลับมาทำต่อได้ ต้องตอบครบก่อนยืนยันไป Stage B
3. Stage B: ตรวจว่ามี Visit ที่เช็คอินจริง จึงบันทึกเริ่มพาชมได้ ไม่สร้าง Visit และไม่ถือว่าเปิด/ส่ง Customer Voices แล้ว
4. Stage C: 7 รายการปิดบ้านและ 6 รายการทบทวน CRM พร้อมความคิดเห็น ข้อกังวล และเวลาลูกค้ากลับจริง ต้องมีงานติดตามเปิดของความสนใจนี้พร้อมกำหนดเวลาที่ยังใช้ได้ก่อนยืนยันจบ SOP ใช้งานติดตามเดิม ไม่สร้างงานหรือ SLA ซ้ำ

ทุกข้อเริ่ม “ยังไม่ตอบ” ไม่มีปุ่มติ๊กครบอัตโนมัติ เลือกทำแล้ว/ไม่เกี่ยวข้อง/ข้ามได้ สองแบบหลังบังคับเหตุผลแยกแต่ละข้อและคงผลไว้ ไม่แปลงเป็นทำแล้ว การติ๊กทบทวนแปลง/สถานะเป็นการรับรองโดย Sales ไม่ใช่คำสั่งแก้ Lead หรือการจอง ให้จัดการข้อมูลจริงผ่านหน้าที่รับผิดชอบเดิม

**SOP ครบไม่เท่ากับ Visit สำเร็จ** ไม่แก้สถานะ Visit, Customer Voices, Lead, KPI หรือการขาย และไม่ส่งแจ้งเตือนอัตโนมัติ

## สิทธิ์และหลักฐาน

- Sales ทุกคนและ Admin/Owner ดูได้ แต่ผู้ทำ SOP ต้องเป็น Sales เจ้าของความสนใจปัจจุบันที่บัญชีใช้งานได้ Admin/Owner ไม่ทำรายการแทน Sales รอบนี้ยังไม่มีเครื่องมือ Admin แก้หลักฐานย้อนหลัง
- ถ้า Admin เปลี่ยนเจ้าของความสนใจ ผู้ดูแลใหม่ทำช่วงที่ค้างต่อได้ การบันทึกครั้งถัดไปเปลี่ยนผู้รับผิดชอบ SOP พร้อมประวัติ ผู้ตอบรายการเดิมไม่ถูกเปลี่ยนชื่อเป็นคนใหม่เมื่อคำตอบไม่เปลี่ยน
- เก็บเวลาที่ Sales ระบุแยกจากเวลาบันทึกเซิร์ฟเวอร์ เหตุผล ผู้ทำ และภาพข้อมูลก่อน/หลังในประวัติที่แก้หรือลบไม่ได้ ลำดับช่วงย้อนกลับไม่ได้ ช่วงที่ยืนยันแล้วไม่แก้ทับ
- ตาม JD เป้าปิดบ้านคือภายในวันเดียวกับลูกค้ากลับใน Asia/Bangkok แต่รอบนี้เพียงเก็บหลักฐาน ไม่คำนวณคะแนน/หักคะแนนหรือให้เครดิตจากการกรอกย้อนหลัง ต้องตรวจนโยบายข้อยกเว้นและเวลาบันทึกจริงก่อนวัด KPI
- ตรวจ revision/สิทธิ์/สถานะในฐานอีกครั้ง การบันทึก SOP/รายการ/ประวัติ/ใบรับเป็นชุดเดียว เมื่อบางส่วนล้มเหลวย้อนทั้งชุด คำขอที่ผลไม่แน่นอนใช้รหัสและข้อมูลเดิม ไม่มีส่งใหม่อัตโนมัติ
- คำขอค้างเก็บชั่วคราวแยกบัญชีในแท็บ อาจมีคำตอบ SOP/สรุปที่ผู้ใช้กรอก ไม่เก็บ token หรือ snapshot ทั้งลูกค้า การเปลี่ยนบัญชีซ่อนข้อมูลเดิม และไม่ใช้ผลกลับจากบัญชีเดิมแสดงในบัญชีใหม่ ขอบเขตนี้ไม่ใช่ระบบ offline หรือการกู้หลังล้างข้อมูล browser

## ยังปิดไว้

หน้า `/sales-crm/sop` และ API `/api/sales-crm/sop` ต้องมีสวิตช์ server `SALES_CRM_V2_ENABLED`, `SALES_CRM_LEAD_WORK_ENABLED`, `SALES_CRM_LIFECYCLE_ENABLED`, `SALES_CRM_VISITS_ENABLED`, `SALES_CRM_VISIT_SOP_ENABLED` เป็น `true` ทุกตัว รวม capability `visit_sop_v1` และ `crm_settings.visit_sop_enabled` ฝั่งฐาน ซึ่งค่าเริ่ม false

ร่าง `sql/sales/25_visit_sop_draft.sql` ใช้ runs/items ในแบบฐานเดิม เพิ่ม revision/เวลาลูกค้ากลับ/อ้างอิงงานถัดไปและประวัติส่วนตัว ยังมี DESIGN ONLY ก่อน DDL และ ROLLBACK **ห้ามนำไปรันบน Supabase** ไม่ใช่ migration ติดตั้ง และไม่เปลี่ยนตาราง/หน้าจอ checklist legacy

ไม่ได้อ่านข้อมูลลูกค้าจริง เชื่อม Supabase เปลี่ยน env/สวิตช์ นำเข้า Deploy หรือเปิดแจ้งเตือนจริง

## งานต่อไปและข้อจำกัด

- Customer Voices ราย Visit และ QR ยังต้องทำต่อ: คำถามเดิม บังคับคะแนน 8 ด้าน ข้อมูลส่วนตัวเพิ่มเติมไม่บังคับ ไม่มีคำตอบล่วงหน้า และปิด Visit พร้อมหลักฐานในรายการเดียว
- แปลงว่างที่เล็งไว้ในแบบเช็คอินยังต้องเชื่อมแยกจากบ้านพาชมของ SOP
- ยังไม่รวมเตรียมบ้านแบบไม่มีนัด/Visit, หลายบ้านใน SOP เดียว, เปลี่ยนบ้านของ SOP เดิม, เปิดช่วงที่ยืนยันแล้วกลับมาแก้, Admin correction หรือบันทึกต่อหลังนัด/Visit ยกเลิกหรือความสนใจ Lost ประวัติเดิมยังอ่านได้
- ต้องตรวจ legacy writers/import/RLS และทดสอบ staging/browser ครบเส้นทางก่อนเตรียม migration ให้ผู้ใช้รันเองและขออนุมัติเปิดจริงแยก

## ผลตรวจ

- ก่อนเพิ่มขั้นนี้ Vitest ทั้งชุดผ่าน 5,436 ข้อ / 144 ไฟล์ (291.71 วินาที หนึ่ง worker)
- หลังเชื่อม focused suite 14 ไฟล์ผ่าน 311 ข้อ (21.55 วินาที หนึ่ง worker) รวม contracts/server/client/pending/UI/ทางเข้าเดิม/ตัวรันทดสอบ ไม่อ้างว่ารันทั้งชุดซ้ำหลังแก้ขั้นนี้
- TypeScript ทั้งโครงการ `noEmit --incremental false` ผ่าน (heap 1152 MB เฉพาะ process) รอบแรกพบชนิดตัวเลือกสถานะสองจุดถูกอนุมานกว้างเป็น string จึงระบุ literal union ให้ตรง contract แล้วรันใหม่ผ่าน ไม่ปิดการตรวจหรือแก้ config
- Scoped ESLint 27 ไฟล์ผ่าน ไม่มี error/warning และ `git diff --check` ผ่าน (มีเพียงข้อความ LF/CRLF ของไฟล์เดิม) ไม่มีการแก้ package/env หรือ config เพื่อให้ผ่าน
- PostgreSQL 17.11 ฐานใหม่แยกบน loopback และข้อมูลสมมติเท่านั้น: `--visit-sop-only` รายงาน `runs/run-GX9NLQ/report.json` ผ่าน **58 assertions และ 6 กลุ่ม concurrency / 19 assertions** รวม READ ONLY และ SQL/TypeScript parity
- ทดสอบร่าง 23 ไฟล์ ตรวจ hash ร่างคงเดิมตลอดการรัน ยืนยัน `stopped=true` และไม่มี postmaster.pid ของฐานทดสอบ รวมรอบก่อน `run-PWalZL` ซึ่งหยุดตอน compile SQL25 เพราะขาดวงเล็บครอบ CASE ในเงื่อนไข แก้ syntax และ assertion ตรงกันแล้วรันฐานใหม่ผ่าน ไม่ผ่อนกฎธุรกิจหรือปิด guard
- ตรวจคำขอเดียวกัน/คนละคำขอเริ่ม SOP ชนนัดเดียวกัน สองแท็บบันทึก revision เดิม เปลี่ยนเจ้าของ/ยกเลิก Visit/ปิด Lost แข่งกับการบันทึก โดยใช้ session แยกและยืนยันว่ารอ lock จริง
- ตรวจเก็บ draft บางข้อครบตาม template, คงชื่อผู้ตอบเดิมเมื่อเปลี่ยนผู้ดูแล, ประวัติแบ่งหน้า, ย้อนทั้งชุดเมื่อบันทึกใบรับล้มเหลว, Next Action ต้องเป็นของขอบเขต/ผู้ดูแลปัจจุบันและยังไม่เลยกำหนด และ SOP completed ขณะที่ Visit ยังคง awaiting_voice

ไม่ได้รัน build/browser E2E/PostgREST/staging หรือชุด native แจ้งเตือนและความจุเดิมซ้ำ ผลนี้ไม่ใช่การรับรอง production หรือการย้ายข้อมูล และยังไม่ใช่ระบบ Customer Voices/QR
