# ตัวอ่านประวัตินำเข้าสำหรับหน้าโครงการ

29 กันยายน 2569 — พัฒนาและทดสอบในเครื่อง ไม่มีเปลี่ยน Supabase/Vercel ไม่มีนำเข้าลูกค้าจริงหรือเปิด flag

## ผลที่ทำแล้ว

เพิ่มตัวอ่าน private `read_prepared_project_sales` ในร่าง `sql/sales/external_project_sales_read_draft.sql` เชื่อม prepared booking → ลูกค้าส่วนกลาง → ความสนใจ/ผู้ดูแลรายโครงการ → ข้อมูลที่หน้า `ProjectSalesWorkspace` ใช้แสดง

- อ่านเฉพาะชุดเตรียมที่ระบุ batch และมี receipt ไม่อ่านหรือ UNION รายการขายเก่ามาบวก จึงไม่มีการนับ 289 รายการเดิมซ้ำกับชุดเตรียมในตัวอ่านนี้
- เลือกโครงการ รวมโครงการปิดแล้ว แยกจอง/โอน/ยกเลิก/ทั้งหมด ค้นหาชื่อ เบอร์ หรือแปลงแบบข้อความตรงตัว และแบ่งหน้าครั้งละ 50 รายการ
- เก็บหนึ่งแถวต่อประวัติ มีรหัส candidate ของตัวเอง ไม่ใช้รหัสขายเดิมจากการเดาชื่อหรือแปลง
- แสดงวันที่ตามต้นทางในช่องหลักฐานแบบวัน ไม่เพิ่มเวลาเที่ยงคืน รอบจอง/จองก่อนหน้า/ส่วนลดที่ไม่มีหลักฐานยังไม่ทราบ
- ยกเลิกที่ไม่ทราบแปลงและเชื่อมลูกค้าได้ยังแสดงพร้อมป้ายพักรายการ ส่วนประวัติที่ยังไม่เชื่อมลูกค้าหรือความสนใจ/เจ้าของแสดงจำนวนรอ Admin ตรวจ **ทั้งชุด** แยกจากตาราง ไม่ถูกทิ้งเงียบ
- ตรวจจำนวนและความตรงกันของ prepared payload กับต้นทางก่อนตัวกรองทั้งหมด รวมตรวจโครงการของแปลงกับ staging interest สำหรับประวัติที่ถูกพักเพราะยังไม่มีผู้ดูแลจริง

## การแยกจากงานจริง

ตัวอ่านนี้เป็น operator-only `STABLE SECURITY INVOKER` ใน private schema ไม่มี public RPC หรือสิทธิ์ client ตรวจ Admin ที่อ้างอิง receipt ยังเปิดสิทธิ์และไม่ถูกแบนก่อนอ่าน ไม่ใช้ metadata ที่ผู้ใช้แก้เองตัดสินสิทธิ์

`parsePreparedProjectSalesSnapshot` เป็นตัวรับผลแยกจาก `parseProjectSalesSnapshot` เดิม ฝั่ง API/client ปฏิบัติงานเดิมยังใช้ตัวรับเดิม และ **ปฏิเสธ prepared snapshot** รวมข้อมูลประวัติแบบวัน/รอบจอง null ไม่เปลี่ยน contract_version หรือให้ flag เปิดโหมดเตรียมได้โดยบังเอิญ

หน้าโครงการรองรับ prepared snapshot ผ่าน interface สำหรับทดสอบที่มีอยู่แล้ว: มีป้าย “ตัวอย่างข้อมูลเตรียมนำเข้า — อ่านอย่างเดียว ยังไม่ใช่รายการขายที่เปิดใช้งาน”, วันที่สำเนา, เลขแถวอ้างอิง, รอบจองไม่ทราบ และจำนวนรายการยังไม่เชื่อม ปิดลิงก์ประวัติจอง/งานสัญญา/สินเชื่อ/โอน/รายงานจริงเมื่อแสดงชุดเตรียม เพื่อไม่ส่ง candidate ID เข้า endpoint ที่รับ sale ID จริง

**ยังไม่มี route หรือ API ที่เปิดชุดเตรียมนี้ให้ผู้ใช้บนเว็บจริง** การเชื่อมต่อในรอบนี้พิสูจน์ในฐานจำลองและทดสอบ component เท่านั้น ไม่ได้เปลี่ยน public.sales หรือสถานะแปลง การเข้าหน้าเดิมจึงไม่ถือว่าเปิดข้อมูลใหม่แล้ว

## การตรวจสอบ

- ทดสอบผล JSON จาก PostgreSQL จริงในเครื่องกับ TypeScript parser ตัวจริง ใน 9 ชุดตัวกรอง และยืนยันว่าตัวรับข้อมูลปฏิบัติงานปฏิเสธผลนี้ทุกชุด
- ทดสอบรวมสถานะ/ค้นหา/หน้า/โครงการ, อ่านโครงการปิด, ป้องกัน role อื่น, Admin ถูกแบน, โครงการของแปลงเปลี่ยน, แยกรหัสจาก legacy sales, ไม่มีการเขียน public data/receipt จากการอ่าน
- เพิ่มข้อมูลสมมติ held booking ที่รู้แปลงแต่ไม่มี owner เพื่อทดสอบว่าหน้าโครงการไม่ล้ม และนับจำนวนรอ Admin ได้ ส่วน unknown-plot cancellation ยังแสดงในตารางเป็นประวัติพักอีกประเภท
- Component tests 19 ข้อผ่าน รวมไม่สร้างลิงก์คำสั่งแม้ context เปิด post-booking, เก็บวันที่แบบวันโดยไม่แปลง timezone และแสดง null เป็นไม่ทราบ
- Unit/component/security guards รอบสุดท้าย 220/220 ผ่านใน 10 ไฟล์; ESLint ไฟล์ที่แก้ผ่าน ไม่ใช่ full app build/E2E
- Native รอบสุดท้าย `node_modules/.cache/buildtrack-sales-runtime/runs/run-6pyaqq/report.json`: reader **19 checks ผ่าน**, booking preparation 34, identity bridge 48 พร้อม account/foundation suites เดิม และหยุดฐานแล้ว (`stopped=true`)

ร่าง SQL ยังคง DESIGN ONLY guard + ROLLBACK ชุดทดสอบใหม่ใช้ `node scripts/sales-runtime/run.mjs --external-project-read-only` และเรียก account/foundation/identity/booking suites เดิมก่อน ไม่รับ URL ฐานจริงหรืออ่าน .env

แนวทาง Supabase/Postgres ทำให้แยกตัวอ่าน private ที่ไม่เพิ่มสิทธิ์ออกจาก API ปฏิบัติงาน ตาม [Database Functions](https://supabase.com/docs/guides/database/functions) ไม่ใช้ผลทดสอบนี้เป็นหลักฐานว่าการสลับข้อมูลจริงพร้อม

## งานที่ยังเหลือ

การแทน public.sales/ตัวอ่านปฏิบัติงานจริงยังต้องมีชุด cutover ที่อนุมัติ: เก็บ legacy history และย้อนกลับได้, ไม่ชนแปลง, ตรวจสิทธิ์และชีตล่าสุด, จัดการ trigger/columns ที่ใช้ร่วมกับฝ่ายอื่น และปรับ booking/lifecycle/report ให้รองรับประวัติ external ก่อนเปิดการทำงาน ขณะนี้งานที่ผ่านคือการเตรียมและอ่านชุดใหม่ให้ตรงกับหน้าโครงการ ไม่ใช่การสลับฐานหรือเปิดให้ Sales ใช้งานแล้ว
